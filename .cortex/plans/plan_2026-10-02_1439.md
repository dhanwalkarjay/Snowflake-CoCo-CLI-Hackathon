## Implementation Steps

1. **Write `tests/test_questions.csv`** — 30 rows: `test_id, category, question, expected_answer, validation_type, validation_sql`
2. **Create `AUDIT.TEST_RESULTS` table** — test_id, category, question, expected, actual_answer, tools_used, pass_fail, run_id, run_at
3. **Run all 30 via AGENT_CHAT** in a stored procedure loop — parse response, extract text, evaluate pass/fail using validation rules (number_match, contains, refusal, not_empty, role_check)
4. **Record results** → show failures
5. **Fix root causes** in agent spec / procedures / data
6. **Re-run** failed tests, update results, report before/after

For governance tests (18–21): run via USE ROLE + direct SQL, not through the agent (agent runs as ACCOUNTADMIN in the current setup). Record role-check results separately.

For report tests (15–17): call GENERATE_REPORT directly and check `narrative_validated`.

**Validation types:**
- `number_match` — extract number from response, compare to expected
- `contains` — response must contain a keyword/phrase
- `refusal` — response must contain refusal language
- `not_crash` — response returned without error
- `report_valid` — narrative_validated = true in JSON
- `role_filtered` — SQL count under a specific role matches expected

## Verification
