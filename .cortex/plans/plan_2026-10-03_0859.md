## Implementation Steps

### Step 1 — Create role SENTINEL_JUDGE
```sql
CREATE ROLE SENTINEL_JUDGE;
GRANT ROLE SENTINEL_JUDGE TO ROLE SYSADMIN;  -- hierarchy best practice
```

### Step 2 — Warehouse USAGE (no OPERATE/MODIFY)
```sql
GRANT USAGE ON WAREHOUSE SENTINEL_WH TO ROLE SENTINEL_JUDGE;
```

### Step 3 — Database + schema USAGE (skip RAW entirely to block FRAUD_TRUTH and all RAW tables)
```sql
GRANT USAGE ON DATABASE SENTINEL_DB TO ROLE SENTINEL_JUDGE;
GRANT USAGE ON SCHEMA SENTINEL_DB.CORE   TO ROLE SENTINEL_JUDGE;
GRANT USAGE ON SCHEMA SENTINEL_DB.RISK   TO ROLE SENTINEL_JUDGE;
GRANT USAGE ON SCHEMA SENTINEL_DB.AUDIT  TO ROLE SENTINEL_JUDGE;
GRANT USAGE ON SCHEMA SENTINEL_DB.DOCS   TO ROLE SENTINEL_JUDGE;
GRANT USAGE ON SCHEMA SENTINEL_DB.APP    TO ROLE SENTINEL_JUDGE;
```
**No USAGE on RAW schema** — this blocks all access including FRAUD_TRUTH. The procedures (owner's rights, owned by ACCOUNTADMIN) still read RAW internally.

### Step 4 — SELECT on tables/views (read-only, no write/DDL)
```sql

GRANT SELECT ON ALL TABLES IN SCHEMA SENTINEL_DB.CORE TO ROLE SENTINEL_JUDGE;
-- RISK (all 4 + linking table)

-- AUDIT (2 tables)

-- DOCS (chunks table — feeds the search service)
GRANT SELECT ON ALL TABLES IN SCHEMA SENTINEL_DB.DOCS TO ROLE SENTINEL_JUDGE;
```
No SELECT on APP tables (they're internal to the app). No SELECT on any RAW table.

### Step 9 — Resource monitor (dedicated, tighter than the existing one)
The existing SENTINEL_RM (150 credits) is shared. Create a **dedicated** monitor with a low cap for the judge:
```sql
CREATE RESOURCE MONITOR SENTINEL_JUDGE_RM
  WITH CREDIT_QUOTA = 10
  TRIGGERS
    ON 80 PERCENT DO NOTIFY
    ON 100 PERCENT DO SUSPEND;
-- Reassign warehouse to the judge-specific monitor? 
```
**Issue:** A warehouse can only have one resource monitor. Since SENTINEL_WH already has SENTINEL_RM (150 credits, suspend at 90%), and changing it would affect all users, the safer approach is to keep the existing monitor (which already suspends at 90% of 150 credits) and note this constraint. Alternatively, we could create a separate small warehouse for the judge.

**Proposed approach:** Create a dedicated `SENTINEL_JUDGE_WH` (X-Small) with a tight 10-credit resource monitor. This isolates the judge's compute budget without affecting other users.
